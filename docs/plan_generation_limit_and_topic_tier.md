# Plan: Per-Tier Daily Generation Limits & Per-Tier Topic Restrictions

> Commit context: "Saved before i added the generation limit and topics that can be generated by tier limit"

## Current State

- **Daily generation counter** exists in `security_config` table (`dailyGenerations` / `dailyGenerationDate`) but the limit check in `checkAndIncrementDailyGenerations()` incorrectly reuses `_previewLimit()` (i.e. the *preview* limit, not a separate generation limit).
- **ConfigService** has `dailyPreviewLimits` and `pdfExportLimits` but no `dailyGenerationLimits` getter yet.
- **Tier gating** for features exists (exam generation, assessment generation, diagrams) via `*_allowed_tiers` lists, but there is no concept of restricting *which subjects/topics* a given tier can generate.
- The lesson editor and exam editor both call `aiService.checkDailyLimit(_subscriptionTier)` before generating, which routes to the DAO's `checkAndIncrementDailyGenerations`.

---

## Phase 1 — Separate Daily Generation Limits from Preview Limits

**Goal:** Introduce a dedicated `daily_generation_limits` config key so AI generation and preview counts use independent quotas.

### Steps

1. **ConfigService** (`lib/core/services/config_service.dart`)
   - Add a new getter:
     ```dart
     Map<String, dynamic> get dailyGenerationLimits =>
         getJsonMap('daily_generation_limits');
     ```
   - Default fallback (if key is absent): `{'free': 0, 'basic': 5, 'standard': 10, 'elite': -1}`.

2. **SecurityConfigDao** (`lib/core/database/daos/security_config_dao.dart`)
   - Add a `_generationLimit(String tier)` private method (mirrors `_previewLimit`) that reads from `_config?.dailyGenerationLimits` with the same hardcoded defaults.
   - Update `checkAndIncrementDailyGenerations` to call `_generationLimit(tier)` instead of `_previewLimit(tier)`.

3. **Payment screen** (`lib/features/payment/screens/payment_screen.dart`)
   - Add a "Daily Generations" row to `_TierComparisonRow` alongside the existing "Previews" row.
   - Wire `dailyGenerationLimits` from ConfigService into the tier comparison table.

4. **Dashboard / credit counter** — optional: show remaining daily generations alongside remaining previews.

### Files touched
- `lib/core/services/config_service.dart`
- `lib/core/database/daos/security_config_dao.dart`
- `lib/features/payment/screens/payment_screen.dart`

## Phase 2 — Per-Tier Topic / Subject Restrictions

**Goal:** Allow the server to declare which subjects (or subject+classLevel combos) a given tier can generate content for. Free users might be restricted to e.g. "Mathematics" and "English"; higher tiers unlock all subjects.

### Steps

1. **ConfigService** (`lib/core/services/config_service.dart`)
   - Add a new getter:
     ```dart
     /// Map of tier → list of allowed subject names.
     /// e.g. { "free": ["Mathematics","English"], "basic": ["*"], ... }
     /// An empty or missing entry means all subjects are allowed.
     Map<String, dynamic> get topicRestrictionsByTier =>
         getJsonMap('topic_restrictions_by_tier');
     ```
   - Add a helper method:
     ```dart
     /// Returns true if [tier] is allowed to generate content for [subject].
     bool isSubjectAllowedForTier(String tier, String subject) {
       final restrictions = topicRestrictionsByTier;
       if (restrictions.isEmpty) return true; // no restrictions configured
       final allowed = restrictions[tier];
       if (allowed == null || (allowed is List && allowed.isEmpty)) return true;
       if (allowed is List) {
         final lower = allowed.map((e) => e.toString().toLowerCase()).toList();
         if (lower.contains('*')) return true;
         return lower.contains(subject.toLowerCase());
       }
       return true;
     }
     ```

2. **Lesson Editor** (`lib/features/lesson/screens/lesson_editor_screen.dart`)
   - In `_handleGenerate()`, after resolving `authTier`, add a subject gate:
     ```dart
     final config = ref.read(configServiceProvider);
     if (!config.isSubjectAllowedForTier(authTier, _subject)) {
       await _showUpgradeRequiredDialog();
       return;
     }
     ```
   - Also gate the "Plan My Term" / bulk generate flow in `LessonsListScreen` at the same point.

3. **Exam Editor** (`lib/features/exam/screens/exam_editor_screen.dart`)
   - Same subject gate in `_handleGenerate()` after the `examGenerationAllowedTiers` check.

4. **Scheme of Work generation** (`lib/features/lesson/screens/lessons_list_screen.dart`)
   - In `_runAutoGenerate()`, check subject restrictions before AI generation.

5. **Payment screen** — optionally add a "Subjects" column to the tier comparison showing e.g. "2 subjects" / "All subjects".
